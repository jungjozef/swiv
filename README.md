# SWIV (Amiga) in Go + Ebitengine

A port of Sales Curve's **SWIV** (Amiga, 1991) to Go and
[Ebitengine](https://ebitengine.org). Game data is read straight from your own
`SWIV.adf`; nothing from the original is included in this repository.

## Run

Put `SWIV.adf` in the working directory.

```sh
go run .                      # title screen, Space -> level 1 (town)
go run . -level 3             # jump to a level (0 town, 1 desert, 2 grass,
                              #   3 river, 4 ice, 5 scifi, 6 final)
go run . -level 0 -top 0xE400 # start further into the level
go run . -level 0 -top 0xE828 -snapshot out.png   # headless one-frame render
go run . -level 0 -weapon 6 -hold-fire 20 -snapshot out.png  # ... after firing
go run . -view                # browse the full-screen .RAW images
go run . -dump-lin sheets/    # contact sheets of every sprite bank
```

In a level: **arrow keys** fly the helicopter, **Space/Z/Ctrl** fire,
**1-6** set the weapon level (no power-ups yet), **PgUp/PgDn** scroll by hand,
**P** pause, **Home** restart, **H** hide the overlay.

`-mute` disables music, `-filter` enables the Amiga low-pass filter. The mod
player is expected at `../protracker-go` (see `go.mod`).

## Layout

```
internal/adf     disk image: directory, LZ unpacker, catalog
internal/raw     full-screen 4-plane images
internal/lin     sprite/scenery banks (images made of chained strips)
internal/pam     level scripts (palette commands + objects)
internal/level   loads a level from AMPROG.OBJ + PAM + LIN, software renderer
internal/font    the game's proportional font (from AMPROG.OBJ)
internal/hud     the status line (separate 1-bit strip, colours 16-31)
internal/weapon  bullet patterns read from AMPROG.OBJ
internal/actor   the original's enemy tasks: kernel layer, helpers, hand-written and lifted routines (lifted.go is generated by tools/lift.py)
internal/enemy   enemy type definitions (hp, score, image) read from AMPROG.OBJ
tools/           Python reverse-engineering tools (see tools/README.md)
docs/            file formats and notes on the original program
```

## Reverse-engineering notes

`docs/formats.md` documents every format decoded so far;
`docs/amprog-notes.md` records how the original program works (kernel,
display, blitter use, level loading).

## In the browser

`tools/build_wasm.sh` builds `web/swiv.wasm` (the `wasm` build selects
`main_wasm.go` instead of `main.go`; there are no command line options, no
development keys and no text line at the bottom of the screen) and copies
`wasm_exec.js`. The page loads `SWIV.adf` from its own directory, so put your
copy there and serve the folder:

```sh
tools/build_wasm.sh
cp SWIV.adf web/
python3 -m http.server -d web 8080   # then open http://localhost:8080
```

`./start-web.sh [port]` does all of this (build, copy `SWIV.adf`, serve on
port 8080, open the browser).

Click the page and press fire (Space / Enter / Z) to start; P pauses.

### GitHub Pages

`.github/workflows/pages.yml` builds the wasm version and publishes `web/`
with the `SWIV.adf` from the repository root (commit it there) on every push to
`master` and when run by hand (Actions, "Deploy to GitHub Pages", "Run
workflow"). Enable it once under Settings, Pages, Source: GitHub Actions. The
workflow clones `jungjozef/protracker-go` next to the repository because
`go.mod` replaces `protracker-go` and `protracker-player` with `../protracker-go`.

### Touch screens

The game draws a virtual pad over the picture (`touchpad.go`): a direction pad
at the bottom left (eight directions, the finger can slide), a round fire button
at the bottom right and two bars at the top right for pause. It shows from the
first touch on, and from the start in a browser that reports a touch screen, and
works next to the keyboard. The fire button also starts the game on the title
screen, leaves the end screens and accepts the high-score name as it is.

The browser build reads the touches itself (`touches_wasm.go`): Ebitengine
converts a touch as if the canvas covered the page, which puts the fingers in
the wrong place in the framed layout. On phones (`pointer: coarse` and a short
side under 600 px) the page drops the frame, title and legend and the game fills
the viewport, keeping its 5:4 shape; tablets keep the framed layout.
